Design System

O guia de como a interface do Dauth é construída: cores, tipografia, componentes e as regras que mantêm tudo consistente. A estética é "Atelier Terracotta": fundo creme, destaque terracota, inputs limpos e bordas finas. Cada salão escolhe uma das 4 paletas, por isso nenhum componente pode ter cor fixa.

01

Princípios

Quatro ideias que resolvem a maioria das dúvidas de design.

Tema primeiro

Toda cor vem de um token CSS (bg-brand, text-ink-2). Se você digitou um hexadecimal dentro de /:salonSlug/*, algo está errado.

Minimalismo

Limpo e padronizado. Bordas de 1px, muito espaço, sem decoração extra. Se duas telas fazem a mesma coisa, elas têm a mesma cara.

Reuse, não copie

Antes de criar um componente, olhe src/components/ui. Componente repetido em duas telas vira um compartilhado.

Estado sempre visível

Carregando, vazio, erro e sucesso têm tela. Botão assíncrono mostra loading. Listas usam skeleton, não spinner solto.

06

Raio, sombra e movimento

Raio de borda

Botão md usa rounded-md; sm usa rounded-sm. Cards de página usam rounded-xl (tabelas em rounded-lg, cartões grandes em rounded-2xl). Chips e avatares são pílula/círculo.

Sombra

shadow-xs
shadow-sm
shadow-md

Sombra só para o que flutua (modal, toast, dropdown). Cards de página usam borda, não sombra.

12

Ícones

Um conjunto único de SVGs em components/ui/Icons.jsx: traço de 1.6px, currentColor, viewBox 24. Use sempre o componente, nunca emoji nem SVG solto.

Precisa de um ícone novo? Adicione o path em Icons.jsx no mesmo estilo (traço, sem preenchimento). Clique em um ícone para copiar o nome.

13

Regras

Aprendidas com bugs reais do projeto.

Cores

  • Nada de #hex, rgba() fixo ou #fff em /:salonSlug/*.
  • Inline style: rgb(var(--token)).
  • Exceção: cores fixas de marca externa (WhatsApp) e status.

Datas e dinheiro

  • Use lib/format.js (formatDate, formatCurrency, formatTime…).
  • Nunca new Date('AAAA-MM-DD') para exibir: some um dia em fuso UTC-3.
  • Valores financeiros passam por MoneyValue (modo "ocultar valores").

Rotas e navegação

  • Todo navigate() e Link dentro do salão leva o slug: `/${salonSlug}/…`.
  • Paths em navItems.js não começam com /.
  • Rota nova precisa de handle: { title }.

Dados e componentes

  • Produto usa api; plataforma usa platformApi.
  • Sidebar do cliente é ClienteSidebar, único. Agenda e Caixa são compartilhados entre Admin e Profissional.
  • Dado que muda acesso (plano, status) nunca vem só do store persistido.

Acessibilidade e testes

  • Botão só com ícone leva aria-label.
  • Campo sem label visível leva aria-label. Os testes E2E procuram pelo que a pessoa vê.
  • Informação nunca só por cor: status também tem texto.

Texto da interface

  • Português do Brasil, direto, sem jargão técnico para o cliente final.
  • Erros dizem o que aconteceu e o que fazer.
  • O nome do produto é "Dauth".
14

Checklist de PR

Antes de abrir o pull request de qualquer tela ou componente.

  • Troquei a paleta (terracota, sage, ocean e midnight) e a tela continua legível?
  • Procurei por cores fixas (#, rgb( sem var)?
  • Reutilizei os componentes de components/ui em vez de copiar?
  • Botões assíncronos usam loading? Listas têm skeleton e estado vazio?
  • Datas, moedas e telefones usam os helpers de lib/?
  • Os links e navigate() levam o slug do salão?
  • Campos têm label; botões de ícone têm aria-label?
  • Rodei npm run build e, se mexi em fluxo, npm run test:e2e?
